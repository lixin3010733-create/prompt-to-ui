# 02 · 工具横向对比：墨刀 / MasterGo / Figma

> 核实时间：2026 年 10 月。功能策略变动频繁，采购或落地前请以各家当期官网说明为准。

三家都在跑「组件 + 图库 + 大模型」这套架构，差别集中在**积木从哪来**。

## 一、先厘清一个误区：Unsplash 不是差异点

常见说法是「AI 调用 Unsplash，所以配图是免费素材」。核实下来，**三家都在用 Unsplash**，不是任何一家的独有能力：

| 工具 | Unsplash 怎么用 | 自动化程度 |
|---|---|---|
| 墨刀 | AI 从提示词提取关键词（如「户外山林」），自动拉取匹配图片放入原型 | 全自动，无需干预 |
| MasterGo | 填充面板内置 Unsplash；AI 按图层语义判断位置（头像位 / 商品位 / 轮播位）填对应类型的图 | 半自动，支持自定义指令 |
| Figma | 需先安装 Unsplash 官方插件并授权，`Cmd/Ctrl + Shift + K` 选中图层填充 | 偏手动，逐图层操作 |

**结论：图库是同质化基建，不构成选型理由。**

## 二、分水岭：组件来源

| | 墨刀 AI | MasterGo AI | Figma agent + Make |
|---|---|---|---|
| 组件来源 | 平台自有组件库 | 预置团队库 / 企业团队库 | 你自己发布的库 |
| 可选的规范 | 平台内置（1 万+组件、5 千图标、1.5 万模板） | Ant Design、Element UI，或企业改造后的自定义库 | 你自己的 design library 与 code components |
| 约束方式 | AI 从平台库中挑选 | 组件属性与 Design Token 强制统一 | agent 默认从「最常用 / 最近用」的组件起步，可 `@` 点名具体 library、token、variable；Make 通过 Make kit（npm 代码包 + 已发布库 + Guidelines.md） |
| 没有设计系统时 | 照样能跑 | 用预置库也能跑 | 只能得到通用脸 |

MasterGo 官方对自己的定位是「**基于设计系统的约束生成**」—— 它把「不能凭空创造组件」这条规则做成了可配置项。

Figma 最激进：**不提供任何通用积木兜底**。官方原话是 agent 会先看你最常用和最近用的组件；没有自己的库，Make 会自己挑一套样式，第一版看着像别人的产品，得推倒重来。

这也修正了流传很广的一个比喻。「大模型是设计师，积木是预制好的大厂积木」——**这句话只对墨刀和 MasterGo 成立**。Figma 的积木是你自己的：你给什么，它才有什么。

## 三、大模型这层：趋同，但有一处关键分歧

| 维度 | 墨刀 | MasterGo | Figma |
|---|---|---|---|
| 生成前是否有中间产物 | **有**。先生成产品功能说明文档，确认后再生成 UI | AI 快搭支持上传 design.md 作为输入 | Make 有 Plan 模式，输出可编辑的 plan.md |
| 模型可选 | 不开放，含 DeepSeek 等国产模型 | 不开放 | **可选** Gemini / Claude / GPT，按任务切换 |
| 中文语境 | 深度优化，理解本土产品术语 | 好 | 一般 |
| 批量编辑 | AI 语义化指令批量改图改文案 | 多选图层生成互不重复的模拟数据 | agent 批量应用组件状态、转暗色模式 |
| MCP 支持 | AI 客户端 + Skill + 本地定时任务 | MasterGo Magic MCP | Figma MCP server（code-to-canvas、download_assets、写回 PR） |

墨刀「**先出文档再出界面**」这个设计值得单独提：它把一次生成拆成「对齐需求」和「施工」两步，代价是多一轮交互，收益是避免方向跑偏。团队里非设计师占比越高，这层缓冲越值钱。

## 四、交付物的三个层级

| | 墨刀 | MasterGo | Figma |
|---|---|---|---|
| 生成结果 | 可点击高保真原型 | 可编辑矢量图层与组件 | 设计层 + Make 的代码层 |
| 代码产出 | CSS、ArkUI 等格式 | D2C Pro 转 React / Vue | 完整可运行项目 |
| 还原度 | 原型级 | 85%–90%（官方头部企业实践口径） | 代码层即真实代码 |
| 能否上线 | 需开发还原 | 缩短前端还原工作量 40%–50% | 可连 Supabase、加登录鉴权、提 PR |
| 计费 | 免费额度 + AI 积分 | AI 设计助手目前以白名单方式向 SaaS 企业版客户开放 | credits 制，不同模型消耗差异大 |

层级越高，越接近能上线的产品；代价是越依赖你先把自己的设计系统建好。

## 五、怎么选

**选墨刀，如果：**

- 团队没有沉淀好的设计系统
- 主要使用者是产品经理而非设计师
- 沟通语境以中文为主
- 想在评审前快速把想法变成可讨论的界面
- 对数据出境有顾虑

**选 MasterGo，如果：**

- 公司已有 Ant Design 或 Element UI 底子
- 需要 AI 产出天然合规于企业规范
- 希望产出物是可编辑矢量图层而不是静态图
- 有私有化或混合部署要求
- ⚠️ 采购前务必先确认 AI 设计助手的开通条件

**选 Figma，如果：**

- 团队已有成熟的 design library 与 code components
- 目标是让 AI 产出**能跑的代码**而不是图片
- 团队是国际化协作
- 愿意投入先把 Make kit 搭起来
